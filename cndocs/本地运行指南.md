# 本地运行指南

## 前置要求

| 工具 | 版本要求 | 说明 |
|------|---------|------|
| Node.js | >= 20.19.0 | 建议使用 nvm 管理版本 |
| pnpm | 9.4.0（锁定） | `npm install -g pnpm@9.4.0` |
| LLM API Key | — | 至少需要一个支持的模型提供商账号 |

> 数据库使用 **SQLite**，无需额外安装数据库服务。

---

## 第一步：安装依赖

```bash
pnpm install
```

---

## 第二步：配置环境变量

将 `.env.example` 复制为 `.env`：

```bash
cp .env.example .env
```

然后编辑 `.env`，**最少需要填写以下 4 个变量**，其余均有默认值或可选：

```env
LLM_PROVIDER=OpenAI        # 模型提供商名称（见下方支持列表）
PROVIDER_BASE_URL=          # 提供商 API 地址（部分提供商必填）
PROVIDER_API_KEY=           # API 密钥
LLM_DEFAULT_MODEL=          # 用于生成页面的主力模型名称
```

还需要填写次要模型（用于摘要、预分析等辅助任务）：

```env
LLM_MINOR_MODEL=            # 推荐填写一个轻量/快速模型，也可与 LLM_DEFAULT_MODEL 相同
```

### 支持的模型提供商

`LLM_PROVIDER` 可填写以下值之一（大小写敏感）：

| 值 | 说明 |
|----|------|
| `OpenAI` | OpenAI 及兼容 OpenAI 规范的接口（如 DeepSeek、Kimi 等）|
| `Anthropic` | Claude 系列 |
| `Google` | Gemini 系列 |
| `Deepseek` | DeepSeek 官方接口 |
| `Qwen` | 通义千问 |
| `DouBao` | 字节豆包 |
| `Kimi` | 月之暗面 Kimi |
| `ZhiPu` | 智谱 GLM |
| `Ernie` | 百度文心一言 |
| `Groq` | Groq 推理加速 |
| `Mistral` | Mistral AI |
| `Cohere` | Cohere |
| `xAI` | xAI Grok |
| `OpenRouter` | OpenRouter 聚合平台 |
| `Together` | Together AI |
| `HuggingFace` | HuggingFace 推理接口 |
| `Hyperbolic` | Hyperbolic |
| `Perplexity` | Perplexity AI |
| `Ollama` | 本地 Ollama（`PROVIDER_BASE_URL` 填 `http://127.0.0.1:11434`）|
| `LMStudio` | 本地 LM Studio |
| `AmazonBedrock` | AWS Bedrock（`PROVIDER_API_KEY` 填 JSON，见 .env.example 说明）|
| `Github` | GitHub Models |

### 常用配置示例

**OpenAI：**
```env
LLM_PROVIDER=OpenAI
PROVIDER_BASE_URL=https://api.openai.com/v1
PROVIDER_API_KEY=sk-...
LLM_DEFAULT_MODEL=gpt-4o
LLM_MINOR_MODEL=gpt-4o-mini
```

**Anthropic Claude：**
```env
LLM_PROVIDER=Anthropic
PROVIDER_API_KEY=sk-ant-...
LLM_DEFAULT_MODEL=claude-sonnet-4-6
LLM_MINOR_MODEL=claude-haiku-4-5-20251001
```

**本地 Ollama：**
```env
LLM_PROVIDER=Ollama
PROVIDER_BASE_URL=http://127.0.0.1:11434
LLM_DEFAULT_MODEL=qwen2.5:72b
LLM_MINOR_MODEL=qwen2.5:7b
```

> **注意**：Ollama 地址不要用 `localhost`，需使用 `127.0.0.1`，否则会有 IPv6 兼容问题。

### 可选：视觉 Sidecar

当主模型**不支持读图**时，可额外配置一个视觉模型，UPage 会先用它生成图片的文字描述，再交给主模型使用。若主模型本身支持读图（如 GPT-4o、Claude 3.x），无需配置。

```env
LLM_VISION_PROVIDER=OpenAI
LLM_VISION_MODEL=gpt-4o-mini
VISION_PROVIDER_BASE_URL=https://api.openai.com/v1
VISION_PROVIDER_API_KEY=sk-...
```

### 关于认证

默认情况下（`LOGTO_ENABLE=false`）**无需配置认证**，应用直接以匿名用户身份运行，适合本地开发。如需启用 Logto 单点登录，参考 `.env.example` 中的 `LOGTO_*` 变量说明。

## 第三步：初始化数据库

```bash
npx prisma migrate deploy && npx prisma generate
```

> **注意**：不要用 `pnpm setup`，那是 pnpm 自身的内置命令（用于配置 PATH），不会执行数据库初始化。

该命令会在 `data/upage.db` 创建 SQLite 数据库并生成 Prisma Client。

---

## 第四步：启动开发服务器

```bash
pnpm dev
```

启动后访问 `http://localhost:5173`。

开发模式下 Vite 和 Express 共用同一进程，支持 HMR 热更新，修改代码后浏览器自动刷新。

---

## 验证运行

打开 `http://localhost:5173`，看到对话输入框即表示启动成功。

输入一段描述，例如"帮我做一个个人主页，简洁现代风格"，点击发送，页面应开始流式生成。若生成失败，检查 `.env` 中的 API Key 和模型名称是否正确。

## 数据库操作

```bash
# 开发中新建迁移（修改 schema 后执行）
npx prisma migrate dev

# 重新生成 Prisma Client（修改 schema 后执行）
npx prisma generate

# 打开 Prisma Studio（可视化查看数据库内容）
npx prisma studio
```

数据库文件路径：`data/upage.db`

## 常见问题

**Q：启动后页面空白或报错 "找不到模块"**

运行 `pnpm install` 确保依赖已安装，再重新 `pnpm dev`。

**Q：生成页面时提示 "Provider xxx not found"**

检查 `.env` 中 `LLM_PROVIDER` 的值是否与支持列表中的值完全一致（大小写敏感）。

**Q：Ollama 连接失败**

确认 `PROVIDER_BASE_URL` 使用的是 `http://127.0.0.1:11434` 而非 `http://localhost:11434`，并确认 Ollama 服务正在运行（`ollama list`）。

**Q：数据库相关错误**

删除 `data/` 目录后重新运行 `pnpm setup`。

**Q：端口冲突**

开发端口为 5173，如需修改，在 `vite.config.mts` 中调整 `server.port`。

# UPage 项目概览

## 项目是什么

UPage 是一个**由大语言模型驱动的可视化网页构建平台**。用户用自然语言描述需求，平台自动生成包含多个页面的完整网站，并提供可视化编辑器进行二次调整，最终支持导出标准 HTML/CSS/JS 代码或直接部署到 Vercel、Netlify、GitHub、1Panel 等平台。

核心能力：
- 自然语言 → 多页面网站（LLM 驱动，流式输出）
- 所见即所得可视化编辑（实时预览，支持拖拽与修改）
- 多轮对话式迭代（保留历史版本，支持回滚）
- 响应式设计，自动适配多端
- 一键部署到主流托管平台

---

## 整体架构

请求从浏览器发出，经 Express 服务器路由到 React Router SSR 层，核心 AI 调用在服务端完成并以流的形式返回，客户端解析流并实时驱动编辑器渲染：

```
用户输入
  │
  ▼
React Router 路由（SSR，Express 托管）
  │
  ├─ 页面路由（/ 首页，/chat/:id 聊天详情）
  │
  └─ API 路由（/api/chat 核心 AI 接口）
       │
       ▼
  .server/llm/agents/page-builder.ts   ← LLM Agent 主入口
       │  准备阶段（摘要 / 上下文 / 设计稿）
       │  Tool Loop（streamText + 工具集）
       │  流式输出 UPageBlock 协议
       ▼
  客户端 SSE 流
       │
  .client/runtime/message-parser.ts   ← 解析流协议
       │
  .client/runtime/action-runner.ts    ← 执行 action
       │
  .client/bridge/index.ts             ← EditorBridge 事件总线
       │
  React 编辑器组件                      ← 实时渲染页面
       │
  Prisma (SQLite)                      ← 持久化消息 / 页面 / Section
```

## 技术栈

| 层次 | 技术 |
|------|------|
| 框架 | React Router v7（framework 模式，SSR 启用） |
| 服务器 | Express（`server.mjs`），生产端口 3000，开发端口 5173 |
| UI | React 19、Radix UI、Framer Motion、React DnD |
| 样式 | UnoCSS（原子 CSS）+ CSS 自定义属性 + SCSS |
| 状态 | Nanostores（客户端）、Prisma（服务端） |
| AI | Vercel AI SDK，支持 OpenAI / Anthropic / Gemini / Ollama 等 20+ 提供商 |
| 数据库 | Prisma ORM + SQLite（`better-sqlite3` 适配器） |
| 认证 | Logto OIDC（可选，`LOGTO_ENABLE=false` 可关闭） |
| 测试 | Vitest + jsdom |
| 代码质量 | Biome（格式化 + 静态分析），Husky pre-commit |

## 核心模块详解

### 1. LLM Agent（`app/.server/llm/`）

所有 AI 调用在此发生，绝不在客户端调用模型。

| 文件 | 职责 |
|------|------|
| `agents/page-builder.ts` | Agent 主入口。组装参数，驱动 Tool Loop，协调各子阶段 |
| `agents/page-builder-draft.ts` | 草稿快照管理。每次 LLM 工具调用后更新内存中的页面草稿 |
| `agents/page-builder-guard.ts` | 守卫逻辑。校验工具调用是否合法，防止 LLM 幻觉操作 |
| `agents/page-builder-context.ts` | 上下文组装。将历史页面快照合并为 LLM 可读的上下文 |
| `agents/page-generation.ts` | 系统提示词构建，控制最大步数限制 |
| `agents/page-builder-tools.ts` | 注册整套工具集（增删改页面 / Section） |
| `preparation.ts` | 准备阶段：生成摘要、设计文档、视觉参考描述 |
| `select-context.ts` | 从多轮历史中挑选有效上下文，控制 token 开销 |
| `structured-page-snapshot.ts` | 解析 LLM 输出的结构化页面快照 |
| `ui-message-stream.ts` | 将 Vercel AI SDK 流转换为前端可消费的 SSE 事件流 |
| `visual-reference.ts` | 视觉 sidecar：当主模型不支持图片时，调用视觉模型生成图片描述 |

**流程概述：**

```
用户消息到达
  → preparation（摘要 + 上下文 + 设计稿，3 路并行）
  → Tool Loop（LLM 调用 add_page / update_section 等工具）
  → 每次工具调用触发 draft checkpoint → 落库 Section
  → 流式推送 UPageBlock 给客户端
```

---

### 2. 客户端运行时（`app/.client/runtime/`）

负责解析服务端推送的流并驱动编辑器。

| 文件 | 职责 |
|------|------|
| `message-parser.ts` | 流式解析 UPage 自定义协议，输出 Action 事件 |
| `structured-message.ts` | 将解析结果组织为结构化消息对象 |
| `action-runner.ts` | 按顺序执行 Action（createPage / updateSection / removePage 等），调用 EditorBridge |
| `page-change-coordinator.ts` | 协调多个 ActionRunner 的执行时序，防止并发冲突 |
| `protocol/` | Action 协议类型定义与标准化（normalize-page-events、materialize-page-action） |

---

### 3. EditorBridge（`app/.client/bridge/index.ts`）

**无头事件总线**，解耦 LLM 运行时与 React 编辑器 UI。

- `ActionRunner` 调用 `bridge.createPage()`、`bridge.updateSection()` 等方法
- 编辑器组件通过 `bridge.on('add_page', handler)` 监听变化
- 通过 `import.meta.hot.data` 在 HMR 热更新时保持实例存活

主要事件：`add_page`、`upsert_page`、`remove_page`、`update_section`

---

### 4. 数据持久化（`app/.server/service/` + Prisma）

| 模型 | 说明 |
|------|------|
| `Chat` | 一次对话会话，含 `urlId`（URL 唯一标识）和 `metadata`（部署平台信息） |
| `Message` | 单条消息（user / assistant），含 `parts`（UI 消息结构）、`revisionId`（版本）、`isDiscarded`（是否丢弃） |
| `PageV2` | 当前页面模型。一条 Message 对应多个 PageV2（每个代表一个页面）。存储 HTML body 及 head 标签 |
| `Section` | PageV2 内的 HTML 片段。含 `actionId`、`domId`、`rootDomId`、`placement`（head/body）、`sort` |
| `PageAsset` | 页面关联的静态资源文件（CSS、图片等） |
| `UserSetting` | 用户配置（category + key/value），`isSecret` 标记 API Key 等敏感字段 |
| `Deployment` | 部署记录（Vercel / Netlify / 1Panel / GitHub） |
| `ChatUsage` | 每条消息的 token 用量统计 |
| `Page` | **已废弃**，旧版一对一页面模型，仅保留兼容 |

---

### 5. 路由结构（`app/routes.ts`）

路由采用集中配置（非文件系统路由），两条页面路由共享同一个 layout：

- `/` — 首页（对话列表）
- `/chat/:id` — 对话详情（编辑器主界面）

API 路由全部在 `/api/` 前缀下，按业务域分组：

| 前缀 | 功能 |
|------|------|
| `/api/chat` | 核心 AI 对话（含流式推送） |
| `/api/project` | 项目文件读取 / 导出 |
| `/api/deployments` | 部署记录查询 |
| `/api/vercel` | Vercel 部署集成 |
| `/api/netlify` | Netlify 部署集成 |
| `/api/github` | GitHub 推送集成 |
| `/api/1panel` | 1Panel 部署集成 |
| `/api/upload` | 文件上传 |
| `/api/enhancer` | 提示词增强 |
| `/api/design-system` | 设计系统配置 |
| `/api/auth` | Logto 认证 |
| `/api/user/settings` | 用户设置 |
| `/assets/users/*` | 用户上传的资源文件访问 |

---

### 6. 服务器（`server.mjs`）

Express 作为统一入口：

- **开发**：以 middleware 模式启动 Vite dev server，支持 HMR
- **生产**：静态资源来自 `build/client`，SSR 由 `@react-router/express` 处理
- 限流：全局 1000 次/分钟，`/api/chat` 单独限 5 次/分钟
- 上传文件从 `STORAGE_DIR`（默认 `./public/uploads`）挂载到 `/uploads`

---

### 7. 样式系统

- **UnoCSS**（原子 CSS）+ `presetUno`
- 暗色模式通过 `[data-theme="dark"]` 选择器切换（非 `prefers-color-scheme`）
- 主题色全部是 CSS 自定义属性，定义在 `app/styles/index.scss`，例如 `var(--upage-elements-bg-depth-1)`
- 自定义图标集：`i-upage:*`，SVG 源文件在 `icons/` 目录
- 常用 shortcut：`transition-base`、`max-w-chat`、`kbd`

## 开发规范

- 包管理器：`pnpm`（锁定 9.4.0）
- TypeScript 路径别名：`~/*` → `./app/*`，类型导入必须用 `import type`（`verbatimModuleSyntax: true`）
- 格式化：Biome，2 空格缩进，单引号，120 字符行宽，尾随逗号
- pre-commit 钩子：先跑 `pnpm typecheck`，再跑 `pnpm check:stage`，任一失败则阻断提交
- 测试：Vitest + jsdom，全局注入 `describe` / `it` / `expect`，路径别名通过 `vite-tsconfig-paths` 解析
